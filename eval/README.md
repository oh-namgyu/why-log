# why-log evaluation (stage 6)

Measures how well `whylog run` recovers design decisions and their reasons when the documents that record
them are hidden. Everything here is generic: data locations come only from a spec file and CLI arguments.

## Files

| file | role |
|---|---|
| `run.py` | driver: isolated clones → `whylog.run` with hide globs → PRE snapshot → mock answers → POST snapshot → score + leak check |
| `clones.py` | `git clone --no-local` at the pinned head (detached, no remote, no other refs); T3 = subject-only messages |
| `mock_user.py` | mock maintainer: answers only with a verbatim quote from a gold reason, else "unknown" |
| `score.py` | 1:1 matching, reason verdicts, metrics |
| `leak.py` | 8-gram overlap between packs and the hidden files |
| `gold_adr.py` | builds a gold file from a repository's ADR directory |
| `report.py` | summary table and a human spot-check sample |
| `bench/` | public benchmark spec and gold files; `results/public/` holds its results |

Every model call goes through `scripts/llm.py` (tool-less, `--safe-mode --tools "" --strict-mcp-config`).
The live source repository is never modified or analysed in place: only clones are.

## Reproduce the public benchmark

Requires the `claude` CLI on `PATH` and Python 3.9+.

```sh
python3 eval/gold_adr.py <clone> --head <sha> --dir <adr dir> --name <name> --out eval/bench/gold/<name>.json
python3 eval/run.py --spec eval/bench/bench.json --work /tmp/whylog-eval --out eval/results/public --jobs 1
python3 eval/report.py --out eval/results/public
```

|---|---|---|---|
| [anton-liauchuk/educational-platform](https://github.com/anton-liauchuk/educational-platform) | `a6f575c3df95acd0e2891f23f8cab229cbb89c87` | `docs/architecture-decisions` | 13 |
| [joshrotenberg/adrs](https://github.com/joshrotenberg/adrs) | `d3b08eaccc6c4d1eee1c7a216694e2ad6d6b7030` | `doc/adr` (not `crates/**/adr-corpus`) | 9 |
| [pypyr/pypyr](https://github.com/pypyr/pypyr) | `b3e8f8c6063c11e37c1c762b89b4cd8620460c79` | `docs/adr` | 5 |

`--source NAME=PATH` points a spec entry at a local clone instead of the URL. Finished stages are cached per
(repo, track) under `--out` (`pre.json`, `answers.jsonl`, `post.json`, `match.json`, `verdicts-*.json`), so a
re-run never repeats a finished reconstruction. `--max-windows` (default 1) refuses a track whose history
needs more than one model window.

Details per repo are in `results/public/<repo>/T2/score.json`; `results/public/summary.md` is regenerated by
`report.py`. Read them with these caveats:

- **Precision is against the ADR list only.** The ADRs are a handful of hand-picked decisions, while the tool
  reports every decision it finds in history, so most unmatched reconstructions are not errors — they are
  decisions nobody wrote an ADR for. The number measures overlap with the ADR set, not correctness.
- **educational-platform leaks through its README**: the README repeats the ADR text, so 180 8-grams shared
  with the hidden ADRs remain in the visible docs (residual). Its recall is not a clean T2 number.
- The judge has not been human-checked for these repos yet.

## Spec format

```json
{"repos": [{"name": "x", "source": "<path or URL>", "gold": "<gold file, relative to the spec>",
            "tracks": ["T2", "T3"], "answers": true, "hide": ["docs/adr", "**/HANDOFF*.md"]}]}
```

The pinned head is taken from the gold file. Gold files follow `why-log-gold/1`:
`{"head", "decisions": [{"id", "title", "decision", "reason", "traceable"}]}`.

## Tracks

- **T2** — the hide globs are removed from the pack (rename-aware: paths, all past versions, diffs, and commits
  that only touched hidden files). Commit messages stay visible.
- **T3** — T2 on a further clone whose commit messages are reduced to their subject line
  (`git filter-branch --msg-filter 'head -n1'`): reconstruction from code, diffs and subjects only.

## Metrics

| metric | definition |
|---|---|
| recall | matched gold with `traceable != false` / gold with `traceable != false` (public ADR gold is unverified: `null`) |
| reasoned recall | matched gold whose reason verdict is `consistent` / same denominator |
| precision | matched reconstructions / reconstructions with confidence ≠ guess |
| contradiction rate | non-guess reconstructions whose matched reason `contradicts` gold, plus unmatched ones whose support-gate verdict is `contradicts` / non-guess reconstructions |
| unsupported rate (gate) | non-guess reconstructions whose support-gate verdict is `unrelated`/`contradicts` / non-guess |
| unsupported rate (model-claimed) | reconstructions the model itself did not call guess whose gate verdict is not `states`/`implies` / those reconstructions |
| question efficiency | (matched ∧ consistent after answers − before) / questions asked (budget 10) |
| mock leak rate | mock answers without a verifiable gold quote / questions asked |
| 8-gram overlap / residual | overlaps between packs and hidden files; residual = overlaps not also present in visible commit messages or diffs |

Matching: one model call lists candidate pairs (`same`/`related`, score) from (id, title, decision) only; only
`same` pairs count, and 1:1 is enforced deterministically (highest score first, ties by id). Reason verdicts:
batched calls, each pair judged from the gold reason vs the reconstructed reason and its verified quotes only:
`consistent | contradicts | unsupported | not-stated`. PRE and POST are scored separately; POST re-judges only
pairs whose reason changed after an answer.

## Limits

- The judge is a model. `report.py --spotcheck` writes a random 20% sample of matched pairs plus all unmatched
  items for a human to verify; numbers are not final until that is done.
- Answers change reasons, not titles, so recall is identical PRE and POST by construction; answers can only move
  reasoned recall and question efficiency.
- The support gate lowers `unrelated`/`contradicts` claims to guess, so the gate-based unsupported and
  contradiction rates over non-guess claims are close to 0 by construction; the model-claimed rate shows how
  often the gate had to intervene.
- Public ADR gold is unverified for traceability, and its reasons come from ADR sections (Context, Why, ...),
  which may be broader than what the implementing commits say. No maintainer is available, so the public
  benchmark reports PRE only (questions are queued, not answered).
- One run per track: model variance is not measured.
